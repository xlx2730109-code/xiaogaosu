# 控制系统

目标：用一块 ESP32-S3 接管四路电调指令，先改善遥控操控，后续接入 Jetson。

当前重点见 [四电机转速排查](../README.md#控制系统)。

## 基准与结论

### A. 软件、固件使用

#### Jetson 串口联调交接

[xiaogaosu_control.ino](xiaogaosu_control/xiaogaosu_control.ino) 为计科交接用单文件，沿用正式版 FW 0.4.0 的控制逻辑。文件头记录编译设置和串口输出格式。已核对源代码一致，Arduino IDE 编译与 Jetson 实机联调待验证。

#### 精简版对照工程

| 工程 | 用途 | 状态 |
| --- | --- | --- |
| [esp32_control_simple](esp32_control_simple/) | 四电调对照，每侧逐个转发有效的接收机脉冲，含串口脉宽监控与定脉宽测试 | 2026-11-25 `FW=SIMPLE-0.3` 编译通过（RAM 19476 B / Flash 308121 B），待烧录和整机架空验证 |
| [esp32_control](esp32_control/) | 正式版，含串口单路测试与调参 | 遥控驱动验收失败，无法解锁，见控制-K84 |

精简版启动串口标识为 `FW=SIMPLE-0.3`，波特率 115200。CH2 转发至 GPIO4/5，CH4 转发至 GPIO6/7。接收机脉宽在 800–2200 µs 内按原宽度转发，每 300 ms 打印一次 `MODE`、输入 `CH2/CH4` 及输出 `OUT_L/OUT_R`。支持串口命令 `HELP`、`FIX <1100-1900>`、`FIX L|R <1100-1900>`（5 秒定脉宽测试，71 Hz 周期）和 `STOP`（立即输出 1500 µs 并恢复透传）。整机架空后按根 README 的阶段 1–2 核对四轮起转脉宽与稳态 RPM。

#### 正式控制工程

在 VS Code 打开 [esp32_control](esp32_control/)，使用左侧 **PlatformIO → Project Tasks → esp32s3_n16r8 → General**。

| 左侧按钮 | 验收 |
| --- | --- |
| **Build** | 编译显示 `SUCCESS` |
| **Upload** | 目标为 ESP32 的 `COM9`，烧录显示 `SUCCESS` |
| **Monitor** | 115200 波特率查看 CH2、CH4 输入与四路输出状态 |

再次烧录前按 Ctrl+C 关闭 Monitor。串口变化时，以 **Silicon Labs CP210x** 对应的端口号为准。

上电后保持锁定。解锁须两路油门同向偏离各自中位至少 100 µs、连续 3 帧，再回中保持 2 秒。

接收机失联时 CH2/CH4 可能回中并继续发帧，当前程序无法单凭这两路识别失联。回中会输出各路 STOP 值，但链路恢复后若摇杆仍在油门位，输出会恢复。整机首测需验证失联表现。

Monitor 命令：`HELP` 查看用法；`STATUS` 查看四路输入输出和各电调参数；`STOP` 立即锁定；`TEST 1 1500` 在锁定状态单路限时输出 5 秒；`SET 1 STOP 1500`、`SET 1 MIN 1248`、`SET 1 MAX 1751`、`SET 1 INV 1` 在 RAM 中调整单台电调参数，重启后恢复源码默认值。Monitor 占用 `COM9` 时不要再开第二个串口程序。执行 `TEST` 前须车轮架空且可立即断开动力。

工程请求 LEDC 为 71 Hz；板上实测返回 70 Hz，周期约 14.285 ms。占空比按 LEDC 实际返回频率换算。构建缓存位于 `E:\HuanCun\AI_tmp\GPT\tmp_20261112_esp32_control\build`，须保留该目录供本机编译。上传和监视端口当前设为 `COM9`，更换 USB 口后检查 `platformio.ini`。

#### 装车前固件准备

装车前完成四路正式固件的编写、编译和烧录。按用户决定，不做独立台架试验；首次电调验证安排在整机接线完成后、车轮架空时进行。

| 阶段 | 验收 | 状态 |
| --- | --- | --- |
| 1. USB 串口 | 确认芯片、存储和日志输出 | 已通过，见控制-K74 |
| 2. 只读遥控 | 核对 CH2、CH4 的中位、范围和失联输出 | 已实测，见控制-K77 |

在 VS Code 打开 [esp32_receiver_test](esp32_receiver_test/)，沿用左侧 **Build → Upload → Monitor**。接收机与 ESP32 共地，`CH2 S` 接 `GPIO15`，`CH4 S` 接 `GPIO16`。串口为 `COM9`，波特率为 115200。依次记录摇杆中位、两端及关闭遥控器后的读数。

车轮架空测试通过前不进行地面行驶。

### C. 控制架构与功能

```text
现有：遥控器 → 接收机两路输出 → 左右各两个电调 → 四台电机
计划：遥控器 → 接收机 → ESP32-S3 → 四路独立电调 → 四台电机
以后：电脑 ─SSH→ Jetson ─USB串口→ ESP32-S3
                                 ↑
                              遥控接收机
```

| 第一版功能     | 作用                                 |
| -------------- | ------------------------------------ |
| 摇杆死区       | 减少回中偏差导致的误动作             |
| 油门变化率限制 | 减少突然推杆造成的猛冲               |
| 最大油门限制   | 控制输出上限                         |
| 差速混控与限幅 | 根据前进、转向指令生成四路输出       |
| 解锁与失联处理 | 启动条件检查、遥控停机、异常输入处理 |

- **控制-K3**：ESP32 置于接收机与电调之间；具体输入协议、电平与电调指令范围须先核实。
- **控制-K4**：没有测速反馈时，限制油门不等于精确限制车速。
- **控制-K7**：油门平滑不能保证消除低速换相抖动；恒速、同步和腿部相位控制需要额外反馈。
- **控制-K8**：现有电调继续承担三相功率驱动，ESP32 只发控制指令，无需另买四套电机驱动板。
- **控制-K14**：Jetson 负责视觉、规划和目标指令；ESP32 负责混控、平滑、限幅及四路输出，两端需编写通信协议。
- **控制-K15**：推荐 SSH 登录 Jetson，再通过 USB 串口控制、看日志及烧录 ESP32。ESP32 默认没有 SSH 服务；[wolfSSH](https://github.com/wolfSSL/wolfssh-examples/tree/main/Espressif/ESP32/ESP32-SSH-Server)可另行集成，但不是完整 Linux 终端，首期不采用。
- **控制-K16**：预留手动与 Jetson 控制权切换、遥控停机优先及指令超时处理；断线不得无限维持最后一条运动指令。

### D. 计划接线：两路输入、四路输出

以下是程序与接线约定，尚未烧录或完成实机验证。CH2、CH4 的左右含义按用户描述记录，上电调试前须核对遥控器设置。

| 方向         | 信号从哪里来    | 接到哪里             |
| ------------ | --------------- | -------------------- |
| 输入左侧指令 | 接收机 CH2 的 S | ESP32 GPIO15         |
| 输入右侧指令 | 接收机 CH4 的 S | ESP32 GPIO16         |
| 输出左前指令 | ESP32 GPIO4     | 左前电调的油门信号线 |
| 输出左后指令 | ESP32 GPIO5     | 左后电调的油门信号线 |
| 输出右前指令 | ESP32 GPIO6     | 右前电调的油门信号线 |
| 输出右后指令 | ESP32 GPIO7     | 右后电调的油门信号线 |

```text
遥控器 ─无线→ 接收机
                 ├─ CH2 S ─→ GPIO15 ─┐
                 └─ CH4 S ─→ GPIO16 ─┤ ESP32 程序读取、处理
                                     ├─ GPIO4 ─→ 左前电调
                                     ├─ GPIO5 ─→ 左后电调
                                     ├─ GPIO6 ─→ 右前电调
                                     └─ GPIO7 ─→ 右后电调
```

- **控制-K21**：GPIO15、16 是计划输入口，GPIO4～7 是计划输出口；程序把左右指令分别生成两路输出，不是引脚内部直通，也不需要把信号线并接。未烧录程序时，空板不会自动分配指令。来源：2026-11-05 接线方案。
- **控制-K22**：接收机与遥控器之间无线通信；接收机到 ESP32 仍需信号线，只供电不能传递摇杆指令。首期使用两路 PWM，未采用 SBUS。来源：原厂 MC7RE-V2 说明书及计划架构。

### E. 供电、共地与插头转接

| 连接               | 方案                                                                                                |
| ------------------ | --------------------------------------------------------------------------------------------------- |
| 接收机供电         | 使用已购UENPO的5V接 +、输出负极接 −，与ESP32共地。早期“一路电调BEC供电”仅为未实测备选            |
| 控制信号地         | 四个电调的细黑地线、接收机 −、ESP32 GND 汇合到同一公共地                                           |
| 电调细红电源线     | 采用独立UBEC后四路全部隔离绝缘，不默认并联，不接ESP32 GPIO；只有改回单路电调BEC方案时才保留选定一路 |
| 开发板供电         | 首期独立 USB 供电；接 Jetson 时核对 USB 供电，避免多路供电回灌                                      |
| 电池、相线、霍尔线 | 四个电调的粗电源线仍各自接动力供电，保留原电机连接；不接 ESP32 GPIO，不经过面包板                   |

```text
电调1细黑地线 ─┐
电调2细黑地线 ─┤
电调3细黑地线 ─┤
电调4细黑地线 ─┼─ 公共地分支线束：可靠焊接并绝缘
接收机 − ─────┤
ESP32 GND ────┘

6S电池现有空闲XT60 ─→ UENPO降压输入 ─稳压5V→ 接收机 ＋
                                       └→ ESP32 5V电源脚，仅脱离电脑供电时接
四个电调 BEC 细红线全部分别隔离；所有地线仍共地
连接电脑USB时，先断开UENPO到ESP32的5V正极支路；接收机可继续由UENPO供电
```

- **控制-K23**：单根连接线叫“地线”；多个设备的地电气相连叫“共地”。接收机 − 必须接入供电负极所在公共地，不能只接正极。四个电调、接收机、ESP32 共六条设备地线；采用独立UBEC时，其输出负极也接公共地。
- **控制-K24**：面包板普通插孔通常每五孔一组相通，长方向整排不通；侧面电源排可能中间断开，两侧电源排也不默认相通。蓝色标线仅作标记，连接 GND 后才指定为地排，使用前用万用表确认导通。来源：[Adafruit 面包板说明](https://learn.adafruit.com/breadboards-for-beginners/breadboard-tips-and-tricks)。
- **控制-K25**：桌面临时转接时，电调三孔母插头的黑线孔可用公对公杜邦线接公共地排；白线孔单独引到输出 GPIO 所在插孔组。接收机针脚、ESP32 排针可用公对母线引到面包板。按实际线序与 S/+/- 核对，不能凭照片中的左右方向插接。
- **控制-K26**：闲置红线可以不剪线、不退针，保持在原插头内且不转接该孔，封住闲置孔；若已退针，金属端子须逐个完整绝缘、固定，不能把裸端子一起包。可拆卸绝缘采用 PVC 电气绝缘胶带，如 [3M Super 33+](https://www.scotchbrand.com/3M/en_US/p/d/b10014694/)，不以防磨布基胶带代替电气绝缘。

#### UENPO输入与5V输出分支

下图按已购模块商品标签，接线前断电并核对实物。正负两支各自连接、分别绝缘；不能仅裸线拧接后包胶带，也不要把输出线直接缠在ESP32针脚上。模块输出接已匹配端子板的5V/GND端子，接收机用母头线接其+/−针脚。

```text
6S空闲XT60 ─ 匹配取电线 ─ UENPO输入：红IN+、黑IN−

UENPO输出：黄OUT+ 5V ─┬─ 接收机＋
                     └─ 可断开支路 ─ ESP32 5V
UENPO输出：黑OUT− ────┬─ 接收机−
                     └─ ESP32 GND及四电调信号地
```

XT60用于本方案的6S输入侧，不是直接把电池接ESP32。若已买带线XT60，将尾线接模块输入即可，不必再次焊接插头本体；裸XT60则先焊好输入线，各焊点套热缩管。USB接电脑时断开图中ESP32外部5V正极支路，共地保持。焊接与绝缘实物教程见[Adafruit导线连接教程](https://learn.adafruit.com/make-it-glow-how-to-solder-neopixels-a-beginners-guide?view=all)。

- **控制-K54**：官方DevKitC-1的外部稳压5V接J1第21针，丝印`5V`；负极接GND，例如J1第22针，丝印`G`。按此前商品图正面、天线在上USB在下，左排最下两针为上`5V`、下`G`，到货仍以实物丝印为准；不是GPIO5，不接`3V3`。使用已核对映射的端子板时接对应5V/GND螺丝端子，原始插针可用匹配母头接线。依据：[乐鑫官方引脚表与供电说明](https://documentation.espressif.com/esp-dev-kits/en/latest/esp32s3/esp32-s3-devkitc-1/user_guide_v1.1.html)。
- **控制-K55**：用户本轮参考照片中的黄色ESP32底板和绿色板不是本机已确认硬件；绿色板型号、供电电压与降压输出去向不能由该照片可靠确定，不据此确认它是电机驱动器。咱们本机四电调粗电源沿用6S动力供电，新增5V模块供ESP32与接收机，不供四电调动力。参考图ESP32虽插USB线，其供电来源也须追线后才能确定。
- **控制-K56**：本轮查到新动模型“航模遥控飞机XT60延长线转接线，带线XT60公头母头带硅胶线15CM”的具体商品索引及淘宝官方优惠入口；公母单头选项未取得实时详情，仍不能替用户确定公母。索引中的m.tb.cn分享短链实际转向双11活动页，不能发送为商品链接；使用其购买表单提供的uland.taobao.com具体优惠入口，库存、当前SKU与结算价未验证。已有配对插头/已买对应尾线则不重复采购。

### F. 常用术语与实物学习

| 名称           | 含义                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------ |
| GPIO           | 可由程序配置的通用输入输出引脚；GPIO4、GPIO5 是两个独立引脚，不是 GPIO45；编号不是排针顺序       |
| S / + / −     | 信号 / 电源正极 / 电源负极；接收机每通道一组三针                                                 |
| PWM            | 用电脉冲的宽度表达指令；航模接收机以脉宽表示通道位置，不是电机实际转速反馈，也不是电机三相动力线 |
| BEC            | 电调内置或独立的稳压供电电路，可由动力电池给接收机供电；有红线不代表输出一定是 5V                |
| Y线            | 一分二线；三芯 Y 线通常把信号、正极、地三路都分接，须避免并联多个 BEC 正输出                     |
| 公头 / 母头    | 公头有金属针，母头有插孔；公对公线可插面包板，公对母线可连接排针与面包板                         |
| 螺丝端子转接板 | 将引脚引出到螺丝夹线端子；两款已买，实际排距与引脚映射待到货核验，不是新增电机驱动器             |

- **控制-K27**：面包板靠内部弹片夹持插针，适合桌面信号与接收机小电流调试；动力电池、电机相线不能接入。捏塑料头垂直插拔，固定面包板与线束并留余量；保护盒不能替代插头防松。正式装机的转接板、固定方式及盒子需统一选型，避免重复购买。来源：[SparkFun 实物图解](https://learn.sparkfun.com/tutorials/how-to-use-a-breadboard/)。
